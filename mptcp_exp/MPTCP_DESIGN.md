# MPTCP 多路径实验 · 设计蓝图(DSN/SSN 二维流量控制)

> 基于 16 节点自由通讯 + 分层 RL + DCQCN + Credit 的实验演进。
> 核心思想:**用 DSN(数据序号)和 SSN(子流序号)构成的二维结构做流量控制**——
> 每个子流有独立的 SSN 序列,所有子流共享同一个 DSN 序列(连接级字节流),
> 流量控制同时作用于两个维度:子流内(SSN)与跨子流(DSN)。
>
> **论文对齐**:面向论文"基于 SDN 全局流量感知的 MPTCP 动态异构子流拥塞控制机制",
> 核心技术路线为 **自定义 TCP(`tcp_stack.py`)+ RL 控制拥塞窗口(`RlCwndController`)**,
> RL 作为 SDN 全局控制器读全网信号(ECN + credit + in_flight)下发 cwnd 决策(见 §8A)。

---

## 1. 目标与范围

### 1.1 要解决的问题
在 16 节点自由双向通讯基础上,支持 **MPTCP 多路径**:
- 每对节点随机生成 **3~4 条子流**
- 其中 **1 条直连(不走交换机)**,其余经交换机
- 用 **DSN/SSN 二维结构**做流量控制,跨三个拥塞域(交换机共享、节点汇聚、直连点对点)
- RL 全局调度 + DCQCN(共享域)+ Credit(点对点域)协同

### 1.2 非目标(本阶段不做)
- 真正的 TCP 内核 MPTCP 协议栈(用自定义流模型模拟)
- 多交换机拓扑(本阶段单交换机 + 直连子流提供路径多样性)
- 真实拥塞窗口(cwnd)——用速率倍率 + 二维序号模拟

## 2. 核心概念:DSN/SSN 二维结构

### 2.1 二维序号模型

```
┌─────────────────────────────────────────────┐
│          MPTCP 连接(逻辑字节流)               │
│     DSN 数据序号:全局唯一,0..N               │
│  ┌──────────┬──────────┬──────────┐          │
│  │ 子流1     │ 子流2     │ 子流3     │          │
│  │ SSN 独立  │ SSN 独立  │ SSN 独立  │          │
│  │ path=sw  │ path=direct│ path=sw  │          │
│  └──────────┴──────────┴──────────┘          │
│  DSS 映射:子流k的 SSN_x = 连接级 DSN_y        │
└─────────────────────────────────────────────┘
```

### 2.2 二维流量控制矩阵

每条流的调度状态是一个 **二维结构**:

```
┌──────────┬───────────────────────────────────┐
│          │        SSN(子流内,行)             │
│  DSN     │  子流1   子流2   子流3  ...         │
│ (列)     │  s1.0    s2.0    s3.0             │
│          │  s1.1    s2.1    s3.1             │
│          │  ...     ...     ...              │
├──────────┴───────────────────────────────────┤
│  每个格子 = (速率, 信用, 路径, 拥塞状态)      │
│  行方向:一条子流内部按 SSN 有序、可重传       │
│  列方向:跨子流按 DSN 重排、保证连接级有序     │
└──────────────────────────────────────────────┘
```

**流量控制的两种操作**:
- **SSN 维度(行)**:控制单条子流内部的发送节奏(限速、重传、credit)
- **DSN 维度(列)**:控制哪些数据交给哪条子流(调度、路径选择)

### 2.3 与三种机制的对应

| 维度 | 作用 | 对应机制 |
|---|---|---|
| SSN(行内) | 单子流可靠传输 + 限速 | Credit(点对点授信)+ 子流速率 |
| DSN(列间) | 跨子流分配 + 有序重排 | RL 调度(哪个 DSN 段给哪条子流) |
| 共享拥塞 | 经交换机子流统一减速 | DCQCN(交换机 ECN 标记) |

## 3. 三域拥塞架构(沿用并强化)

### 3.1 拥塞域划分

```
拥塞域 ①:交换机(共享瓶颈)
  所有经交换机的子流共享
  → DCQCN:队列深 → ECN 标记 → 这些子流统一降速
  → 直连子流不经过交换机 → 不受 ECN 影响(不误伤)

拥塞域 ②:节点接收侧(汇聚)
  节点同时接收"交换机子流 + 直连子流"
  → Credit:按子流授信,防止汇聚溢出

拥塞域 ③:直连链路(点对点)
  节点间直接 veth,无共享瓶颈
  → Credit:接收方授信,发送方额度内发
```

### 3.2 机制 → 信号 → 动作

| 位置 | 拥塞性质 | 机制 | 信号 | 动作 |
|---|---|---|---|---|
| 交换机出口 | 共享 | DCQCN | ECN 标记(ecn_marks) | 经交换机子流量化降速 |
| 直连链路 | 点对点 | Credit | 直连接收方授信水位 | 直连子流额度内发 |
| 节点接收侧 | 汇聚 | Credit | 节点各子流 credit 水位 | 防止某子流独占缓冲 |
| 全局 | 跨所有 | RL | ECN + credit + 时延 + 丢包 | 各子流速率/路径/DSN分配 |

## 4. 数据结构设计

### 4.1 flow.py 扩展

```python
class Subflow:
    """一条子流 = 一个 SSN 序列 + 一条路径。"""
    def __init__(self, sid, src, dst, path, rate=1.0):
        self.sid = sid
        self.src = src
        self.dst = dst
        self.path = path              # 'direct' 或 'sw'
        self.rate = rate              # RL 低层控制的速率倍率
        self.active = True
        # SSN 维度状态
        self.ssn_next = 0             # 下一个要发的 SSN
        self.ssn_unacked = 0          # 已发未确认的 SSN 数(伪 cwnd)
        self.ssn_credit = 0           # 该子流当前信用额度(credit)
        self.ssn_credit_grant = 20    # 接收方一次授信多少
        # 拥塞状态
        self.ecn = 0.0                # 经交换机子流:ECN 标记率
        self.delay = 0.0
        self.loss = 0.0

    def ssn_state(self):
        """SSN 维度状态向量(给 RL 用)。"""
        return (self.ssn_next, self.ssn_unacked, self.ssn_credit, self.ecn, self.delay)

class Flow:
    """一条逻辑连接 = 一个 DSN 序列 + 多条子流。"""
    def __init__(self, fid, src, dst, n_subflows=1, direct_ok=True):
        self.fid = fid
        self.src = src
        self.dst = dst
        self.subflows = []
        # DSN 维度状态
        self.dsn_next = 0             # 下一个要分配数据的 DSN
        self.dsn_received = 0         # 已收到(重组到)的 DSN
        self.reorder_buf = {}         # 乱序缓冲:dsn -> payload
        for k in range(n_subflows):
            # 每条流 1 条直连(如果允许)+ 其余经交换机
            path = 'direct' if (direct_ok and k == 0) else 'sw'
            self.subflows.append(Subflow('%d.%d' % (fid, k), src, dst, path))

    def dsn_state(self):
        """DSN 维度状态向量(给 RL 用)。"""
        return (self.dsn_next, self.dsn_received, len(self.reorder_buf))
```

### 4.2 二维流量控制矩阵

```python
def build_flow_matrix(flows):
    """把所有流组织成 DSN/SSN 二维结构,便于 RL 统一调度。
    matrix[dsn][ssn] = (flow_id, subflow_id, path, rate, credit)"""
    matrix = {}
    for f in flows:
        for sf in f.subflows:
            # 这个子流的 SSN 段 = 它负责的 DSN 区间
            matrix[(f.fid, sf.sid)] = {
                'src': sf.src, 'dst': sf.dst, 'path': sf.path,
                'rate': sf.rate, 'credit': sf.ssn_credit,
                'ssn_next': sf.ssn_next, 'dsn_next': f.dsn_next,
            }
    return matrix
```

## 5. RL 状态/动作/奖励设计

### 5.1 状态(全局,含两维信号)

```
状态向量 = [
  # 共享拥塞域(交换机)
  sum(各经交换机子流 ecn), max(各端口 ecn_marks),
  # 点对点域(直连)
  各直连子流 credit 水位,
  # 汇聚域(节点)
  各节点接收缓冲占用,
  # SSN 维度
  各子流 (ssn_unacked, ssn_credit, rate),
  # DSN 维度
  各流 (dsn_next - dsn_received, 乱序缓冲大小),
]
```

### 5.2 动作

```
动作 = [
  # SSN 维度:每条子流速率倍率(×1.2/1.0/0.7/0.4)
  rate[subflow_i]  ∀i,
  # DSN 维度:每个新 DSN 段分配给哪条子流(路径选择)
  dsn_assign[dst] → subflow_j,
]
```

### 5.3 奖励

```
R = 总吞吐利用率
  − λ × 平均时延            (跨子流,含直连)
  − μ × 丢包率              (credit 应该把它压到 0)
  − ν × DSN 乱序程度        (惩罚不均衡调度造成的重排)
  − ρ × 子流间不公平        (各子流速率方差)
```

**关键**:奖励里加入"乱序惩罚"——防止 RL 把所有流量塞进快的那条子流导致接收端 DSN 重排严重。

## 6. 拥塞控制闭环(二维 + 三域)

```
┌──────────────────────────────────────────────────────┐
│                  控制面(RL 全局调度)                   │
│  读状态:ECN(共享)+ credit(点对点)+ DSN/SSN 进度       │
│  → 决策:各子流速率 + DSN 分配                         │
└──────┬───────────────────────┬───────────────────────┘
       │ 经交换机子流            │ 直连子流
       ▼                        ▼
┌──────────────┐          ┌──────────────┐
│ DCQCN 拥塞域  │          │ Credit 拥塞域 │
│ 交换机 ECN →  │          │ 接收方授信 →  │
│ 统一降速       │          │ 额度内发送    │
└──────┬───────┘          └──────┬───────┘
       │                          │
       └──────────┬───────────────┘
                  ▼
        接收端 DSN 重组(乱序缓冲)
        按 DSN 排成有序字节流
                  │
                  ▼
        反馈:ACK(SSN)+ 数据确认(DSN)→ 发送端
```

## 8B. 交换机异构 + 成本感知调度(已实现)

让"动态异构子流"真正成立,从三个维度给 3 台交换机制造真实差异,并在 RL 中引入成本因素:

### 异构维度与实现

| 维度 | 方法 | 配置 | 效果 |
|---|---|---|---|
| **带宽** | P4 meter(令牌桶,按出口端口) | sw1=25M / sw2=60M / sw3=140M | 每条交换机路径带宽上限不同 |
| **拥塞敏感度** | 不同 `ecn_thresh` 寄存器 | sw1=5 / sw2=20 / sw3=60 | 同样拥塞下打 ECN 的时机不同 |
| **链路特征** | `tc netem`(内核级时延/丢包) | sw1=WiFi(10ms±2,1%)/ sw2=蜂窝(30ms±10,2%)/ sw3=光纤(2ms) | 真实时延/抖动/丢包差异 |

**验证**:3 台交换机 `bw=25/60/140 Mbps, ecn_thresh=5/20/60` 生效;tc 应用后 DSN 重组出现真实异构代价(59/60 收到,26 有序——慢路径时延致段迟到)。

### 成本感知 RL

为每条路径定义**单位流量成本**(模拟异构接入的经济性):
```
PATH_COST = {'direct': 0.1, 'sw1': 0.0(免费WiFi), 'sw2': 1.0(贵蜂窝), 'sw3': 0.2}
COST_WEIGHT = 0.5
```

- **路径选择**(`_path_pressure`):压力 = 占用 + 0.6×ECN + 成本 → 拥塞相近时优先便宜路径
- **训练奖励**(`rl_train_mptcp.py`):`R = 吞吐 − λ时延 − μ丢包 − 0.5×成本`
- **效果**:RL 学到"性能相近时用便宜路径,贵路径(蜂窝)只在必要时用"

**这是论文的关键创新点**:在传统"吞吐/时延/丢包"目标上加入**成本维度**,让异构子流调度在经济上最优——对齐"动态异构子流拥塞控制"的实践价值。

## 9. 关键设计决策与取舍

1. **直连子流为什么不打 ECN**:直连不经过交换机,交换机看不到它;如果硬让交换机打标,直连子流也没走交换机。所以直连用 credit,交换机用 ECN——**信号来自各自的拥塞域**。
2. **为什么 credit 按子流而不是按链路**:一个节点接收多个源的子流,若 credit 整链路授信,一条子流会独占缓冲饿死其他子流。
3. **为什么奖励加"乱序惩罚"**:MPTCP 的 DSN 重排是开销;如果不惩罚,RL 会只选"最快的那条子流",丧失多路径价值。
4. **伪 cwnd(ssn_unacked)**:用"已发未确认 SSN 数"模拟 TCP 的 cwnd,不实现真实 ACK 滑动窗口——因为实验是 UDP 载体,重点在调度而非传输协议细节。
